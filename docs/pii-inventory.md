## 3. ช่องทางที่ข้อมูลรั่วได้จริง (เรียงตามความเสี่ยง)

1. **GitHub repo สาธารณะ** — `data/surveys/*.json` (180 ไฟล์) + `DATABASE.xlsx`/`Fixed_Database*.xlsx`: ใครก็โหลดได้ไม่ต้องล็อกอิน และ git history เก็บทุกเวอร์ชัน (รวมข้อมูลที่พยายามลบ)
2. **การแสดงผลในแอป** — client ดึงไฟล์เต็มจาก GitHub มาตาราง/รายงาน → ผู้ใช้ทั่วไปที่เปิด r2.dev เห็นชื่อ/เบอร์ได้
3. **CDN snapshot** — ลดแล้วในรอบ v2.11.4 (dashboard/onedrive/github) แต่ `/api/database` ยังคงตามนโยบาย
4. **localStorage ของแต่ละเครื่อง** — เก็บสำเนารายการที่บันทึก (ไม่รวม base64 ถ้าเกิน quota)
5. **ไฟล์สำรองในเครื่อง** — `survey-*.json` ที่ `save_survey()` เขียนไว้ที่ root (ปัจจุบัน `.gitignore` ยังไม่กัน → งาน `B6`)

## 4. ทางเลือกการแก้ (พร้อมต้นทุน/ผลกระทบ)

| ทางเลือก | ลดความเสี่ยงได้จริงแค่ไหน | ต้นทุน/ผลกระทบ | สถานะในแผน |
|---|---|---|---|
| (ก) ทำข้อมูลเป็น private repo + ให้แอปอ่านผ่าน proxy | **สูงสุด** — ปิดช่อง 2.1/2.2 ทั้งหมด แต่ยังต้องมีที่เก็บรูป/รายงาน | ต้องมี Workers/API + จัดการ credential ฝั่งเซิร์ฟเวอร์; คนนอกทีมเข้าถึงข้อมูลต้องผ่านสิทธิ์ | `B8` (P1+P2) |
| (ข) Cloudflare Worker proxy (read+write) โดยเก็บ PAT เป็น secret | สูง — browser ไม่เห็น credential และอ่านผ่าน proxy ได้ | ต้องตัดสินใจสถาปัตยกรรม + สิทธิ์ Cloudflare + งานฝั่ง client | `B8` |
| (ค) ลด/ปกปิดฟิลด์ก่อน commit (เช่น เบอร์โทรแบบปิดบางส่วน, เก็บชื่อเล่น) | กลาง — ลดการรั่วของฟิลด์ที่ sensitive ที่สุด แต่กระทบคุณภาพรายงาน A4 | ต้องแก้ schema + UI + รายงาน; ข้อมูลเก่าใน history ยังอยู่ | ยังไม่อยู่ในแผน (ข้อเสนอใหม่) |
| (ง) คงไว้ + ยอมรับความเสี่ยง (พร้อมจำกัดการเข้าถึง repo) | ต่ำ | ไม่มีงานเพิ่ม แต่ยอมรับความเสี่ยงถาวร | สถานะปัจจุบัน |

**ข้อเสนอของ P3**: เลือก (ก) เป็นเป้าหมายระยะกลาง โดยมี (ข) เป็นวิธีดำเนินการ และระหว่างรอ ให้ทำ (ค) เฉพาะ `contactPhone` (เพราะเป็นฟิลด์ที่ระบุตัวบุคคลได้มากที่สุด) และเปิด `R2_STRIP_STATION_CONTACTS=1` ใน workflow หากยอมรับว่าฟอร์มจะไม่เติมข้อมูลอัตโนมัติบน r2.dev
